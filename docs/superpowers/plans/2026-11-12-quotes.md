# Quotes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A section "Angebote": quotes entered like ordinary invoices, numbered `A<year>-<seq>` with revisions, printed as the invoice layout titled `**** ANGEBOT ****` (one PDF, no copy), declined/reopened/deleted while they have no invoice, and converted with one confirmed click into an ordinary invoice from their latest version.

**Architecture:** A quote version is a row shaped like an `Invoice` row (`RootId`, `RevisionNumber`, `IsLatestRevision`, snapshots, lines), stored in its own tables (`Quotes`, `QuoteLines`, `QuoteDocuments`, `QuoteNumberCounters`) so nothing that reads invoices can see it. The chain's state (`Open`/`Declined`/`Converted`) and its invoice id are kept equal on every row of the chain. Conversion lives in `InvoiceService`, inside the transaction that allocates the invoice number. The frontend reuses the invoice editor, revision list and list-page patterns with a `kind` switch.

**Tech Stack:** .NET / EF Core (SQLite) / ASP.NET OData, QuestPDF, xUnit + PdfPig; Vue 3 + PrimeVue + TanStack Query, generated OData client; Playwright.

**Spec:** `docs/superpowers/specs/2026-11-12-quotes-design.md` (read §2 first; "Claude's call" rows are approved with the rest).

## Global Constraints

- Branch `feat/quotes` off `main`. Never push; never start the dev stack on 8080; never run `scripts/reset-dev-db.sh`; never read `data/` or `export/`.
- Code and docs in English; every UI string in `frontend/src/i18n/de.json`, German only. Fixed names: menu "Angebote", page button "Neues Angebot", actions "In Rechnung umwandeln", "Ablehnen", "Wieder öffnen", "Angebot löschen", "Angebot herunterladen", states "Offen", "Abgelehnt", "Umgewandelt", invoice back-link "Aus Angebot <number>", PDF heading `**** ANGEBOT ****`, PDF metadata/continuation "Angebot <number>".
- Quote number: `A{year}-{sequence:D4}` (`A2026-0001`), revision `A2026-0001-R1` (same `-R` marker as invoices). Year = local year at creation of the original. Sequence per year from 1, never reused, also after deleting the highest.
- Error codes (400, `{ error: { code, message } }`): `QuoteNotFound`, `QuoteNotOpen` (edit, decline, convert of a quote that is not open), `QuoteNotDeclined` (reopen), `QuoteConverted` (delete). Existing codes reused as they are: `NoLines`, `RecipientNotFound`, `RecipientAddressRequired`, `PriceRequired`, `InvalidPrice`, `InvalidCount`, `ItemNotFound:<id>`.
- Exactly one new EF migration, `Quotes`, created in Task 2 via `scripts/ef.sh migrations add Quotes --project src/Invoicing.Api` (from `backend/`); if a later task needs schema, regenerate that same migration (remove + add) rather than adding a second. Existing migrations stay untouched.
- New actions follow `CreateInvoice`: `POST odata/<Action>`, camelCase body, PascalCase success JSON, ValidationException → 400, unexpected → logged 500. Registered in `EdmModelBuilder`. Hand-typed in `frontend/src/api/endpoints.ts`.
- Backend tests: `docker compose stop backend`, clear `backend/**/bin|obj` on NETSDK1064, `scripts/dotnet.sh test Invoicing.sln`.
- Frontend: `npm run typecheck && npm run lint && npm run build` clean. After the EDM change `npm run gen:odata` against the E2E stack and commit `src/api/metadata.xml` with `src/api/generated/`.
- E2E only via `cd e2e && npm test …` (own stack on 8081), helpers from `e2e/vue.ts`, unique names from `e2e/unique.ts`, every test seeds its own data. `npm run stack:down` afterwards.
- Every task updates the `docs/spec.md` requirements it touches (Task 2 adds a user story "Quotes" and the first FRs; later tasks extend them). Conventional Commits, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Two conversions of the same quote at once (double click, two tabs) must produce exactly one invoice; the other is refused with `QuoteNotOpen`. Pinned in Task 4.
2. Deleting the quote with the year's highest number and then creating a quote must give the next number, not the deleted one. Pinned in Task 3.
3. Revising an older version of a quote continues the chain's revision numbers, and conversion always takes the latest version, never the one that was edited. Pinned in Tasks 2 and 4.
4. A recipient whose address was emptied after the quote was made: conversion is refused with `RecipientAddressRequired`, the quote stays open, and no invoice number is used up. Pinned in Task 4.
5. A quote from last year converted this year gets an invoice number of this year, and its revisions keep their `A<last year>` number. Pinned in Tasks 2 and 4.
